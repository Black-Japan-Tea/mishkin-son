# Mishkin Son — план разработки v1

> **Статус:** утверждённый план (фаза аудита завершена). Кода нет — только план.
> **Источник решений:** структурированный опрос из 100 вопросов + 1 уточнение (2026-10-21).
> **Рабочее название:** «Мишкин сын» (репозиторий `mishkin-son`); финальное название придумаем позже.

---

## 1. Обзор продукта

Мобильное веб-приложение (PWA) — суточный трекер времени младенца. Родители в одно нажатие
фиксируют сон и кормления (в том числе ночные «перекусы» без прерывания сна), видят историю,
статистику и получают мягкие советы встроенного офлайн-советчика. Работает офлайн: события
пишутся в локальную базу и синхронизируются с облаком (Supabase) при появлении сети.

**Ключевой сценарий (ночь):** нажал «Сон» → пошёл таймер (с нуля, текстом «1 ч 47 мин») →
ночью тап по карточке → «Поел» (сон продолжается, кормление вложено) → утром «Проснулся».
Всё записано, даже если интернета не было всю ночь.

## 4. Профиль ребёнка

Поля v1: **имя, дата рождения, пол, вес и рост при рождении, фото-аватар**.

- Возраст отображается автоматически: дни → недели → месяцы («3 нед 4 д» → «4 мес 12 д»).
- Недоношенность в v1 не учитывается (нормы от даты рождения; поле гестационного возраста
  можно добавить позже без миграции событий).
- Выбор ребёнка при запуске (если детей > 1), далее — последний активный + переключатель в шапке.

## 5. События: модель и сценарии

Единая сущность «событие» (таблица `events`) с типами: `sleep` (сон), `feed_breast`,
`feed_bottle`, `feed_solid`, `feed_water`, `diaper`. Детали — в JSONB-поле `details`.

### 5.1 Сон

- Тег **день/ночь — вручную** при старте (при сбитом режиме точнее автоматики).
- Старт: фиксируется текущее время + долгое нажатие открывает правку; можно указать
  **условия**: место (кроватка/коляска/на руках) и заметку.
- Таймер считает `now − время засыпания` (надёжно при закрытии приложения, блокировке
  экрана, перезагрузке). Формат — текстом: «1 ч 47 мин». На карточке также время засыпания.
- Тап по карточке сна → панель **«Проснулся» / «Поел»**.
- Случайное нажатие: кнопка «Отменить» доступна 30–60 секунд, дальше — удаление из истории.
- Аномальная длительность (дневной сон > 4 ч или период > 12 ч) → мягкая карточка
  «Так и было?» с подтверждением времени пробуждения.

### 5.2 Ночные кормления внутри сна

- «Поел» **не прерывает сон**: кормление записывается вложенным событием
  (`parent_event_id` → активный сон), таймер сна продолжается.
- Минимум данных ночного кормления: **факт + время + объём в мл** (быстрый ввод).
- После «Поел» панель остаётся: можно «Поел» ещё раз или «Проснулся».
- В истории: метки-кормления внутри полосы сна; длительность сна считается целиком.

### 5.3 Кормления (общая модель)

- Типы v1: **грудь, бутылочка, прикорм, вода**.
- **Таймер есть только у грудного** (сторона: лево/право/обе + длительность) — решение
  зафиксировано уточнением к Q26/Q28.
- Бутылочка: **объём в мл обязателен**; прикорм: тип еды + заметка; вода: отметка/мл.
- Бутылочка/прикорм/вода — **мгновенная запись со временем завершения**, без таймера.
- Вне сна кнопка «Еда» открывает bottom sheet с выбором типа.
- События могут идти **параллельно** со сном (и друг с другом) — никаких жёстких блокировок.

### 5.4 Подгузники (в v1)

- Одна кнопка с выбором типа: попис / кака / оба.

### 5.5 Антропометрия (в v1)

- Журнал измерений: вес, рост, окружность головы (ручной ввод после визитов к врачу).
- Графики по нормам ВОЗ (центильные кривые).
- Сцеживание как отдельное событие — **нет** (достаточно типа «бутылочка (сцеженное)»).
- Здоровье (температура, лекарства, симптомы) — **v2**.

## 6. Правки, удаление, защита от ошибок

| Решение | Выбор |
|---|---|
| События задним числом | Да, полная форма (день + время + все поля) |
| Редактирование | Все поля, в любой момент |
| Удаление | Мгновенное в UI (с подтверждением); физически — soft-delete `deleted_at` (§11) |
| Защита от «забыл остановить» | Предупреждение при аномальной длительности + карточка «Так и было?» |

> Важно: «мгновенное удаление» — только визуальное. Для корректного офлайн-синка удаление
> обязано оставлять tombstone (`deleted_at`), иначе событие «воскреснет» при следующей синхронизации.

## 8. Офлайн и синхронизация

| Решение | Выбор |
|---|---|
| Локальная база | **IndexedDB** через обёртку `idb` |
| Стратегия | Офлайн-first: статика и данные живут локально, сеть — только для синка |
| Триггер синка | Появление интернета (событие `online`) + ручная кнопка в настройках |
| Конфликты | **Last-write-wins** по `updated_at`; события уникальны по uuid — конфликтов мало |
| Офлайн-доступ | Кэш последних **7 дней** истории |
| Индикация | Иконка + счётчик несинхронных в настройках, рядом с кнопкой синка |

**Механика:** каждое событие рождается на клиенте с `uuid v4` и пишется в IndexedDB
одновременно в store `events` и в очередь `outbox`. Outbox дренируется на сервер при синке
(идемпотентные upsert'ы по uuid), после подтверждения — очищается. Тянем с сервера события
с `updated_at > cursor` за последние 7 дней; более старая история — по запросу при наличии сети.

### 9.1 Сравнение топ-3 бесплатных хостингов

| | **Vercel (Hobby)** | **Netlify (Free)** | **Cloudflare Pages (Free)** |
|---|---|---|---|
| Трафик | 100 GB/мес | 100 GB/мес | Безлимитный (soft limits) |
| Сборки | 100/день (быстрые) | 300 мин/мес | 500/мес |
| Превью на PR | Да | Да | Да |
| Особенности | Лучший DX для Vite/Next | Edge Functions, Forms | Workers 100k req/день, самый быстрый CDN |
| Ограничение | Hobby — некоммерческое | — | — |

### 9.2 Supabase: важные ограничения free-плана

- Проект **ставится на паузу после ~7 дней неактивности**. Для ежедневного трекера риск низкий,
  но в план включить восстановление из паузы + напоминание о риске.
- Лимиты: 500 MB БД, 50k MAU — для одной семьи запас многократный.

## 10. Схема данных (Supabase Postgres)

Все времена — **`timestamptz` в UTC**; отображение — по часовому поясу устройства
(перелёты обрабатываются автоматически). Все таблицы с мультитенантностью семьи закрыты **RLS**.

- **`profiles`** — `id` (= `auth.users.id`), `display_name`, `avatar_url`, `created_at`.
- **`families`** — `id`, `name`, `created_by`, `created_at`.
- **`family_members`** — `family_id`, `user_id`, `joined_at`. Без ролей в v1: членство = право
  на чтение и запись. Приглашения — по email через токен-таблицу `family_invites`.
- **`children`** — `id`, `family_id`, `name`, `birth_date`, `sex`, `birth_weight_g`,
  `birth_height_cm`, `avatar_url`, `created_at`, `deleted_at`.
- **`events`** — сердце системы:
  - `id` (uuid, генерирует **клиент** — офлайн-безопасно),
  - `child_id`, `family_id`, `created_by`,
  - `type` (`sleep | feed_breast | feed_bottle | feed_solid | feed_water | diaper`),
  - `started_at` (`timestamptz`), `ended_at` (nullable — активный сон = `NULL`),
  - `parent_event_id` (nullable — вложенное ночное кормление внутри сна),
  - `details` (jsonb: сторона груди, мл, тег день/ночь, место, заметка, тип подгузника),
  - `created_at`, `updated_at`, `deleted_at` (tombstone для LWW-синка).
- **`measurements`** — антропометрия: `child_id`, `type` (`weight|height|head`),
  `value`, `measured_at`, `created_at`, `deleted_at`.
- **`user_settings`** — `user_id` (PK), `theme_mode` (`light|dark|system|schedule`),
  `theme_schedule_start`, `theme_schedule_end`, `last_child_id`.

Локальная схема IndexedDB (зеркало): stores `events` (индекс `child_id + started_at`),
`children`, `measurements`, `outbox` (очередь на отправку), `meta` (`sync_cursor`,
`last_child_id`).

## 11. Дизайн-система

Референс компонентов — 21st.dev (мобильные паттерны); тёмная тема — cursor/zcode-стиль.

### 11.1 Светлая тема («пастельная, постельная»)

- Фон: **тёплый крем/беж** (ориентир `#FAF6F0`), поверхности — полупрозрачный белый
  (`rgba(255,255,255,0.9)`), текст — мягкий графитово-коричневый.
- Акценты интерфейса: **персик + шалфей**.
- Семантические цвета: зелёный — успех, красный — ошибка, оранжевый — внимание,
  фиолетовый — информация/подсказки.
- Шрифт: **округлый** (Nunito или Quicksand), крупная дружелюбная типографика.
- Компоненты: скругления 16–24px, лёгкие тени, много воздуха.

### 11.2 Тёмная тема (cursor/zcode-стиль)

- Фон: **тёплый тёмный** (ориентир `#17140F`, поверхности `#201B15`), hairline-границы
  `rgba(255,255,255,0.10)`.
- Контраст: **soft-dark** — приглушённые тона, щадящие глаза ночью.
- Акценты — **смысловые роли**: зелёный — сон/успех, оранжевый — еда/внимание,
  фиолетовый — ИИ/навигация.
- Без градиентов; свечение — только амбиентное (§11.4).

### 11.3 Режимы темы

Четыре режима в настройках:

1. **Светлая** — всегда светлая.
2. **Тёмная** — всегда тёмная.
3. **Авто** — следует системной теме устройства.
4. **По расписанию** — в настраиваемом окне (по умолчанию **22:00–07:00**) тёмная,
   вне окна — светлая. Расписание работает как самостоятельный 4-й режим.

Хранение: локально (мгновенное применение) + синхронизация в `user_settings` (переезжает
с аккаунтом). Переключение — плавный fade ~200 мс.

### 11.4 Амбиентная подсветка (рецепт z.ai)

Изучено на chat.z.ai: эффект «мягкого ореола» строится не на неоне, а на
**полупрозрачной подложке + hairline-границе + очень рассеянной тени**:
`0 4px 16px rgba(0,0,0,0.05)`, переход ~150 мс. Переосмысливаем под палитру:

- **Светлая тема:** нейтральный оттенок тени, как у z.ai (тёплый тон даёт сам фон крема).
- **Тёмная тема:** тень/ореол подкрашивается семантическим цветом элемента
  (альфа ~8–14%): зелёный у сна, оранжевый у еды.
- **Применение (утверждено):**
  1. **Карточка активного сна** — зелёный амбиентный ореол + медленное «дыхание»
     (пульсация с циклом ~6 с); при `prefers-reduced-motion` дыхание отключается.
  2. **Кнопки «Сон» и «Еда»** — мягкое свечение своим цветом (зелёный / оранжевый),
     усиливающееся в активном состоянии.
- Остальные поверхности (карточки, bottom sheet'ы) — просто z.ai-рецепт: полупрозрачность +
  hairline + нейтральная мягкая тень, без цвета.

## 12. Нейро-советчик («лёгкая нейронка»)

**Ядро — детерминированный офлайн-движок**: правила + справочные нормы + статистика ребёнка.
Никакого ML и облачных LLM в v1 (быстро, бесплатно, объяснимо, работает офлайн).

| Решение | Выбор |
|---|---|
| Основа советов | Нормы ВОЗ/NSF по возрасту **+ личные паттерны** ребёнка (скользящие средние) |
| Горизонт анализа | **30 дней** истории + возрастной контекст |
| Показ | **Отдельный экран «Советы»**, без карточки на главном |
| Когда | **Только по запросу** (открыл раздел — движок посчитал) |
| Прогноз окна сна | **Да**: «ближайшее окно сна ~13:20» по медианному окну бодрствования |
| Тон | Мягкие наблюдения («дневных снов меньше обычного»), без давления |
| Дисклеймер | Постоянная пометка «не медицинская рекомендация» |

Механика: на вход — события за 30 дней + возраст; справочник норм сна/бодрствования по
месяцам (встроенная таблица); правила сравнивают факт с нормой возраста и личной нормой
ребёнка; на выходе — список наблюдений + прогноз окна сна. Пересчёт лёгкий — на лету при
открытии экрана, без фоновой работы.

## 14. Приватность и безопасность

- Доступ к данным — **RLS**: членство в `family_members` = единственный путь к строкам
  ребёнка/событий; транспорт — HTTPS (встроено в Supabase).
- Без сторонней аналитики и трекеров.
- Удаление аккаунта и полного документа данных — **не в v1** (вернёмся в v2).
- Бэкапы: средства платформы Supabase + локальная копия событий на устройстве (офлайн-кэш).
- Экспорт данных пользователем: **JSON** (CSV — позже).

## 17. Риски и меры

| Риск | Мера |
|---|---|
| Supabase free ставит проект на паузу после ~недели неактивности | Ежедневная активность семьи снимает риск; задокументировать процедуру восстановления |
| Мгновенное удаление + офлайн-синк | Обязательно `deleted_at`-tombstone, иначе удаление «воскреснет» |
| LWW теряет редкие параллельные правки | События append-mostly и уникальны по uuid; правки одного поля — приемлемый риск; наблюдать |
| iOS PWA: пуши/напоминания капризны | Пуши сознательно вынесены из v1 |
| Пользователь меняет системные часы | Таймер всегда `now − started_at`; при синке серверное `updated_at` приоритетнее |
| Нормы сна — чувствительная тема | Только диапазоны ВОЗ/NSF + постоянный дисклеймер «не медицинская рекомендация» |
